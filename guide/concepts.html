How pyRadtran works#

pyRadtran turns an xarray dataset of places and times into an xarray dataset of radiative-transfer results. It writes one libRadtran (uvspec) input file per point, runs them in parallel, and puts the outputs back on the dimensions of the input.

 your Dataset                 pyRadtran                         result Dataset
┌──────────────┐   ┌──────────────────────────────────┐   ┌─────────────────────┐
│ time         │   │ 1. merge config layers           │   │ your dims            │
│ latitude     │──▶│ 2. validate params vs libRadtran │──▶│ + wavelength         │
│ longitude    │   │ 3. one .inp file per point       │   │ + altitude           │
│ (sweep dims) │   │ 4. uvspec × N in parallel        │   │ edir, edn, eup, …    │
│ (variables)  │   │ 5. parse + reshape + provenance  │   │ status, attrs        │
└──────────────┘   └──────────────────────────────────┘   └─────────────────────┘

The rest of this guide covers these five steps.

The input dataset#

Three names are required:

Name

Role

time

UTC timestamp of each point; sets the solar zenith angle and day of year

latitude, longitude

degrees north / east; used for the solar geometry and to select ERA5 / radiosonde profiles

 
import pandas as pd
import xarray as xr
import pyradtran                      # registers ds.pyradtran

ds = xr.Dataset(
    coords={
        "time": pd.date_range("2025-06-21 06:00", periods=5, freq="3h"),
        "latitude": ("time", [78.9] * 5),
        "longitude": ("time", [11.9] * 5),
    }
)

For other names pass time_var=, lat_var=, lon_var= to run().

Every dimension is a loop#

pyRadtran simulates the outer product of all dimensions of the dataset. A dataset with dims (time: 5) is 5 simulations; add a dimension albedo: 4 and it becomes 20, and the result has dims (time, albedo, …). A parameter sweep is a dataset dimension:

import numpy as np
from pyradtran import Var

ds = xr.Dataset(
    coords={
        "time": [pd.Timestamp("2025-06-21 12:00")],
        "latitude": ("time", [78.9]),
        "longitude": ("time", [11.9]),
        "albedo": np.linspace(0.05, 0.9, 5),          # sweep axis
    }
)
ds["surface_albedo"] = ds.albedo                      # variable to reference

res = ds.pyradtran.run(
    config_path="config/solar_broadband.yaml",
    params={"albedo": Var("surface_albedo")},         # per-point value
)
res.eup.dims
# ('time', 'albedo', 'altitude')

A data variable can live on any subset of the dimensions: a variable on time varies along the track, one on albedo varies along the sweep axis, one on both varies over the full grid.

Note

If a sweep dimension has the same name as an output column you request (sza, albedo), the column is returned as sza_out / albedo_out so it does not clash with the coordinate.

Tip

The number of uvspec runs is the product of all dimension sizes. Check np.prod(list(ds.sizes.values())) before a large sweep, and drop dimensions you do not want to loop over.

Altitude#

altitude (km) means different things as a coordinate and as a data variable:

Layout

Meaning

Result

altitude is a dimension / coordinate

output levels of one simulation (zout 0 1 2 …)

an altitude dimension with those levels: a vertical profile from one uvspec call per point

altitude is a data variable (e.g. on time)

the sensor altitude of each point (zout per point)

one level per point: an aircraft track

 
# vertical profile at every time step
ds = ds.assign_coords(altitude=("altitude", np.arange(0, 10.5, 0.5)))

# aircraft track: altitude changes along time
ds["altitude"] = ("time", [0.1, 2.5, 5.0, 5.0, 3.0])

Without any altitude, the config’s output_altitudes_km is used (default: surface).

From dataset to input file#

For each point, three sources are merged into one input file. Later ones win:

  1. Config: the merged YAML layers (Configuration), i.e. solver, spectral range, output columns, atmosphere file, defaults for albedo etc.

  2. params literals: the same value for every point (Parameters & Validation).

  3. params Var(...) references: a different value per point, read from your dataset.

pyRadtran adds what depends on the point: the solar zenith angle from time and location (unless you set sza), the day_of_year for the Sun–Earth distance and, if requested, per-point atmosphere and cloud files from ERA5 or radiosondes (Atmosphere & ERA5, Clouds).

explain() shows the result, tagged by source, without running:

print(ds.pyradtran.explain(
    config_path="config/solar_broadband.yaml",
    params={"albedo": Var("surface_albedo"), "mol_modify O3": 320.0},
))

rte_solver disort                                                          # config
mol_abs_param reptran coarse                                               # config
data_files_path /opt/libRadtran-2.0.6/data                                 # config
atmosphere_file /opt/libRadtran-2.0.6/data/atmmod/afglus.dat               # config
mol_modify H2O 2.0 MM                                                      # config

The solar zenith angle#

Unless sza is given (in the config or via params), it is computed per point (calculate_solar_zenith_angle()):

\[ \cos\theta_0 = \sin\varphi\,\sin\delta + \cos\varphi\,\cos\delta\,\cos h, \qquad h = 15^\circ\left(t_\mathrm{UTC} + \frac{E_t}{60} - 12\right) + \lambda \]

with latitude \(\varphi\), longitude \(\lambda\) (east positive), UTC time \(t_\mathrm{UTC}\) in hours, and the solar declination \(\delta\) and equation of time \(E_t\) (minutes) from the Fourier series of Spencer (1971). It agrees with the NOAA solar calculator to about 0.2°; atmospheric refraction is not included. Naive timestamps are read as UTC, timezone-aware ones are converted. To impose your own geometry, pass params={"sza": Var("my_sza")}.

Running in parallel#

Each point is an independent uvspec process. execution.max_workers sets how many run at once; execution.timeout_seconds stops runs that hang. Points fail individually: a failed or skipped point becomes NaN with a non-zero status (Results & Post-Processing) and the batch continues. Only a batch where every point fails raises PyRadtranError.

Measured cost per point on one core (libRadtran 2.0.6). Spectral resolution and solver dominate, so start coarse:

Setup

Time per point

twostr, lowtran, 350–2500 nm spectral

~0.5 s

disort, reptran fine, 8–13 µm spectral radiance

~1 s

disort, reptran coarse, 300–3500 nm broadband

~3.5 s
