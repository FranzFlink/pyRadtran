pyradtran.interface.PyRadtranAccessor.run#

PyRadtranAccessor.run(config_path=None, config=None, params=None, parameter_overrides=None, time_var='time', lat_var='latitude', lon_var='longitude', albedo_var=None, surface_temperature_var=None, surface_type_var=None, era5_atmosphere=None, era5_clouds=False, return_dataset=True, save_to_file=True, output_path=None, progress_callback=None, cloud_wc_var=None, cloud_ic_var=None, cloud_reff_var=None, cloud_ic_reff_var=None, cloud_top_var=None, cloud_bottom_var=None, show_progress=True, channels=None, keep_spectral=False)[source]#

Run uvspec for every point in the dataset.

Every combination of the dataset’s dimensions is one uvspec simulation. The result has the same dimensions plus wavelength and altitude.

Input dataset.

  • time (UTC), latitude (degrees north) and longitude (degrees east) are required; map other names with time_var / lat_var / lon_var. time must be a coordinate; latitude and longitude may be data variables. Solar runs compute the solar zenith angle and day of year from them unless sza is set.

  • Every dimension is a simulation axis. A time dimension with latitude/longitude along it is a track or time series; a (time, latitude, longitude) grid runs every combination; any extra dimension (albedo, sza, cloud_top …) is a sweep axis. A dataset without dimensions (scalar time, latitude and longitude) is one point; its result has only wavelength / altitude.

  • Data variables and coordinates are per-point inputs for Var in params and for the cloud_*_var arguments.

  • altitude (km, fixed name) is special:

    • as a coordinate, its unique sorted values are the zout levels of every simulation, replacing simulation_defaults.output_altitudes_km. As a dimension it is not iterated: one run returns all levels.

    • as a data variable, it is a per-point output altitude (e.g. an aircraft track), short for params={"zout": Var("altitude")}. An explicit "zout" in params wins. The result holds each point’s altitude in the variable zout.

Parameters:

  • config_path (str or pathlib.Path, optional) – Simulation YAML, merged over the package defaults and the master config (~/.pyradtran/config.yaml) by load_config(). With neither config_path nor config, those two layers are used alone.

  • config (SimulationConfig, optional) – Pre-built configuration; takes precedence over config_path. It is copied, so the caller’s object is not modified.

  • params (dict, optional) –

    Per-run parameters on top of the configuration. Keys are uvspec option names ("albedo", "sza", "mol_modify O3", "aerosol_default" …) or dotted config paths ("simulation_defaults.wavelength_nm", "execution.max_workers"). Values are

    • a literal, applied to every point; lists/tuples are space-joined ({"wavelength": [400, 700]}), "" or True gives a bare keyword;

    • Var ("name"): the value of dataset variable or coordinate name at each point;

    • Raw (value): a literal passed through without validation;

    • for "wc_file" / "ic_file", a dict {"z": [...], "lwc" | "iwc": [...], "reff": [...]}, written to a cloud file (see format_cloud_profile()).

    Literals are validated before anything runs (see pyradtran.describe()). Preferred over the deprecated *_var and parameter_overrides arguments.

  • parameter_overrides (dict, optional) – Deprecated; use params.

  • time_var (str) – Names of the time / latitude / longitude variables. Defaults "time", "latitude", "longitude".

  • lat_var (str) – Names of the time / latitude / longitude variables. Defaults "time", "latitude", "longitude".

  • lon_var (str) – Names of the time / latitude / longitude variables. Defaults "time", "latitude", "longitude".

  • albedo_var (str, optional) – Deprecated; use params={"albedo": Var(...)}.

  • surface_temperature_var (str, optional) – Deprecated; use params={"sur_temperature": Var(...)}.

  • surface_type_var (str, optional) – Deprecated; use params={"brdf_rpv_type": Var(...)}.

  • era5_atmosphere (xarray.Dataset, optional) – ERA5 pressure-level data (temperature and specific humidity, optionally ozone and cloud water) used as the atmosphere of each point instead of a scaled standard profile. CDS or ARCO-ERA5 naming is normalised with pyradtran.era5.normalize_era5(). The nearest column in time and space is written to a radiosonde-format file per point. Gases in that file are not rescaled: the config h2o_mm is ignored, and so is ozone_du when the dataset has an o3 field.

  • era5_clouds (bool or dict, default False) – Also derive per-point cloud profiles (wc_file / ic_file) from the ERA5 clwc / ciwc fields. A dict (possibly empty) is passed to pyradtran.era5.cloud_profiles() (e.g. {"reff_water_um": 8.0}). Cloud settings in params or cloud_*_var win. Requires era5_atmosphere.

  • return_dataset (bool, default True) – Return the results dataset; with False, the path of the saved file.

  • save_to_file (bool, default True) – Write the results to NetCDF.

  • output_path (str or pathlib.Path, optional) – Destination file; parent directories are created. Default: <paths.output_dir>/<output.filename_prefix>_ <YYYYmmdd_HHMMSS><output.filename_suffix> is used.

  • progress_callback (callable, optional) – callback(completed, total), called in the main process after every finished point.

  • cloud_wc_var (str, optional) – Dataset variables with the liquid / ice water content (g m-3) of one homogeneous cloud layer per point.

  • cloud_ic_var (str, optional) – Dataset variables with the liquid / ice water content (g m-3) of one homogeneous cloud layer per point.

  • cloud_reff_var (str, optional) – Effective-radius variables (µm) for liquid and ice. Missing or NaN values fall back to 10 µm (liquid) / 20 µm (ice). Without cloud_ic_reff_var the ice phase uses cloud_reff_var.

  • cloud_ic_reff_var (str, optional) – Effective-radius variables (µm) for liquid and ice. Missing or NaN values fall back to 10 µm (liquid) / 20 µm (ice). Without cloud_ic_reff_var the ice phase uses cloud_reff_var.

  • cloud_top_var (str, optional) – Cloud top / base altitude variables (km). Required with cloud_wc_var / cloud_ic_var. Points where either is NaN run cloud-free.

  • cloud_bottom_var (str, optional) – Cloud top / base altitude variables (km). Required with cloud_wc_var / cloud_ic_var. Points where either is NaN run cloud-free.

  • show_progress (bool, default True) – Show a tqdm progress bar (if tqdm is installed).

  • channels (xarray.DataArray, optional) – Instrument spectral response functions, dims (channel, wavelength). For spectral results, every spectral variable is SRF-averaged onto a channel dimension with convolve_channels(); the returned (and saved) dataset is in channel space.

  • keep_spectral (bool, default False) – With channels, also keep the original spectral variables under <name>_spectral.

Returns:

xarray.Dataset or pathlib.Path – With return_dataset=True (default) the results dataset:

  • Dimensions: the simulated input dimensions, in input order, then wavelength (nm; absent for wavelength-integrated output) and altitude (km; always present). With channels, channel replaces wavelength.

  • altitude coordinate: output levels in km (float), i.e. the zout levels of a multi-level run or the one level all points share (0.0 for the surface default). With a per-point output level (altitude data variable, "zout": Var(...)) the coordinate is the placeholder 0.0 (select with isel(altitude=0) or squeeze("altitude")) and the data variable zout (km, on the input dimensions) holds each point’s level. The placeholder also stands for a symbolic level ("zout": "toa").

  • Data variables: one per uvspec output column (simulation_defaults.output_columns, e.g. edir, edn, eup), in uvspec’s units. Failed or skipped points are NaN. A column named like an input coordinate, typically a sweep dimension such as sza or albedo, is returned as <name>_out (sza_out) with a logged warning.

  • status: integer flag on the input dimensions: 0 ok, 1 failed (uvspec error or timeout), 2 skipped (missing time or NaN latitude/longitude).

  • Attributes: provenance, i.e. pyradtran_version, history, pyradtran_params (JSON), pyradtran_config (the merged configuration as YAML), pyradtran_libradtran_bin, pyradtran_input_example (annotated input file of the first point) and, with channels, pyradtran_channels / pyradtran_keep_spectral.

With return_dataset=False, the path of the NetCDF file holding the same dataset.

Raises:

  • PyRadtranError – If a required variable is missing from the dataset, the ERA5 dataset lacks temperature / humidity / pressure_level (or cloud water with era5_clouds), all simulations fail, or both return_dataset and save_to_file are false.

  • ValidationError – If params has an unknown option, an invalid literal, a Var naming a variable not in the dataset, or a bare string equal to a dataset variable name (use Var).

  • ValueError – If cloud variables lack a boundary variable or are missing from the dataset.

Warns:

DeprecationWarning – If parameter_overrides or one of the *_var surface arguments is used.

Notes

Layers. Each point’s input file is built from three layers, later ones winning:

  1. the configuration, merged from package defaults, the master config and config_path (see load_config());

  2. params literals, the same for every point;

  3. params Var references, resolved per point from the dataset.

explain() shows the result with each line tagged by its layer. Dotted keys in params edit layer 1 for this call only.

Missing values. A point with missing time or NaN latitude/longitude is skipped (status == 2). A Var parameter that is NaN at a point is dropped for that point: the configuration value applies, the point runs and reports status == 0. Mask such points yourself if you do not want the fallback.

Failures. A failing point does not abort the batch: its values are NaN, status is 1, and the uvspec error and the path of the kept .inp file go to <paths.working_dir>/failures_<timestamp>.log. PyRadtranError is raised only when every point fails.

Parallel execution. execution.max_workers simulations run concurrently in worker processes (None: one per CPU; 1: serially in the calling process, best for debugging). Change it per call with params={"execution.max_workers": 8}. A uvspec run is killed after execution.timeout_seconds.

Clouds. The cloud_*_var arguments describe one vertically homogeneous layer per point, written as a two-level libRadtran cloud file (see inspect_cloud_file()). For vertically resolved clouds pass a profile dict as params["wc_file"] / params["ic_file"] or use era5_clouds. The twostr solver can return NaN for optically thick clouds; use "rte_solver": "disort" for cloudy runs.

Files. Input, output and cloud files are written to paths.working_dir (relative to the current directory if relative) and removed after a successful run when execution.cleanup_temp_files is true. ERA5 atmosphere files are kept in its era5_atmospheres/ subdirectory.

Examples

These use config/quickstart.yaml from the Quickstart (solar spectrum 350–2500 nm, edir / edn / eup at the surface) and need libRadtran.

>>> import numpy as np
>>> import pandas as pd
>>> import xarray as xr
>>> import pyradtran
>>> from pyradtran import Var
>>> ds = xr.Dataset(
...     coords={
...         "time": pd.date_range("2025-06-21T08:00", periods=3, freq="4h"),
...         "latitude": ("time", [61.0, 61.0, 61.0]),
...         "longitude": ("time", [22.0, 22.0, 22.0]),
...     }
... )

Saving. By default the result is also written to an auto-named file in paths.output_dir. Choose the file and return only the path:

>>> path = ds.pyradtran.run(  
...     config_path="config/quickstart.yaml",
...     output_path="out/quickstart.nc",
...     return_dataset=False,
... )
>>> path  
PosixPath('out/quickstart.nc')
>>> xr.open_dataset(path).status.values  
array([0, 0, 0])

Failed and skipped points are flagged. The second point fails in uvspec (sun below the horizon); the third has no latitude:

>>> bad = ds.assign(sun=("time", [30.0, 95.0, 60.0]))
>>> bad["latitude"] = ("time", [61.0, 61.0, np.nan])
>>> result = bad.pyradtran.run(  
...     config_path="config/quickstart.yaml",
...     params={"sza": Var("sun")},
...     save_to_file=False,
... )
>>> result.status.values  
array([0, 1, 2])
>>> result.edir.sel(wavelength=550).squeeze("altitude").round(1).values  
array([1385.1,    nan,    nan])
>>> ok = result.where(result.status == 0)
