pyradtran.input_builder.InputFileBuilder#

class InputFileBuilder(config)[source]#

Bases: object

Build provenance-tagged uvspec input lines.

The merged configuration provides the baseline input file. The resolved params of one point (from resolve_point()) replace or extend it. Every line records its origin.

Parameters:

config (SimulationConfig) – Merged configuration (package defaults, master config and project YAML, with dotted params overrides already applied).

config#

The configuration passed in; read on every build() call.

Type:

SimulationConfig

See also

pyradtran.params.ParamResolver

Produces the resolved mapping.

pyradtran.interface.PyRadtranAccessor.explain

User-facing preview built on build() and render_annotated().

Examples

The input file for one point (needs valid libRadtran paths; output from libRadtran 2.0.6):

>>> from datetime import datetime
>>> from pyradtran import ParamResolver, load_config
>>> from pyradtran.input_builder import InputFileBuilder
>>> config = load_config()  
>>> resolver = ParamResolver(  
...     config,
...     {
...         "albedo": 0.85,
...         "wc_modify": ["tau550 set 12"],
...         "aerosol_default": True,
...         "mol_modify O3": False,
...     },
... )
>>> builder = InputFileBuilder(config)  
>>> lines = builder.build(  
...     datetime(2024, 6, 21, 12), 78.9, 11.9, resolver.static_params()
... )
>>> print(builder.render_annotated(lines))  
rte_solver twostr                                                   # config
mol_abs_param lowtran per_nm                                        # config
data_files_path /opt/libRadtran-2.0.6/data                          # config
atmosphere_file /opt/libRadtran-2.0.6/data/atmmod/afglus.dat        # config
mol_modify H2O 2.0 MM                                               # config
source solar /opt/libRadtran-2.0.6/data/solar_flux/NewGuey2003.dat  # config
sza 55.69                                                           # config
day_of_year 173                                                     # config
wavelength 400 3600                                                 # config
output_user lambda sza eglo eup albedo                              # config
zout 0.0000                                                         # config
umu 1.0                                                             # config
albedo 0.85                                                         # params-literal
wc_modify tau550 set 12                                             # params-literal
aerosol_default                                                     # params-literal
quiet                                                               # config

"mol_modify O3": False removed the config’s ozone line; sza was computed from time and position.

__init__(config)[source]#
build(dt, latitude, longitude, resolved=None, radiosonde_path=None, era5_atmosphere_file=None)[source]#

Build the full ordered line list for one simulation point.

Parameters:

  • dt (datetime.datetime) – Time of the point (UTC). Sets day_of_year and, when no sza is configured, the solar zenith angle.

  • latitude (float) – Position in degrees (north / east positive). Used only for the computed solar zenith angle.

  • longitude (float) – Position in degrees (north / east positive). Used only for the computed solar zenith angle.

  • resolved (dict, optional) – {key: (value, provenance)} as returned by resolve_point(). Not modified.

  • radiosonde_path (pathlib.Path, optional) – Radiosonde file. Used (as radiosonde <path> H2O RH) only when the config has h2o_source: radiosonde and no ERA5 file is given.

  • era5_atmosphere_file (pathlib.Path, optional) – Atmosphere file written by pyradtran.era5. Takes precedence over radiosonde_path. Its gas columns are read from the file header.

Returns:

list of InputLine – The input file, one entry per line, in output order.

See also

render, render_annotated

calculate_solar_zenith_angle

Fallback for the sza line.

effective_output_columns

Decides the output_user line.

Notes

Lines tagged config are written first, in a fixed order:

  1. rte_solver, mol_abs_param, data_files_path, atmosphere_file;

  2. radiosonde (ERA5 or radiosonde profile, if any);

  3. mol_modify O3 ... DU / mol_modify H2O ... MM from ozone_du / h2o_mm, skipped for a gas whose profile comes from the radiosonde/ERA5 file, so a measured column is never rescaled by the config scalar;

  4. source; for solar runs sza (config value, else calculate_solar_zenith_angle()) and day_of_year; for thermal runs sur_temperature if configured;

  5. wavelength and, for integrated runs, output_process integrate;

  6. albedo (if configured), output_user, zout (levels in km, sorted and de-duplicated), umu 1.0 for nadir viewing, and the wc_file / ic_file lines of a cloud_source: file configuration.

Catalog short names (afglss, kurudz_1.0nm; see list_atmosphere_profiles() and list_solar_spectra()) are resolved to files in paths.libradtran_data on the atmosphere_file and source solar <file> lines, whether they come from the configuration or from resolved. Anything else is taken as a path and written unchanged.

A cloud_source: parametric configuration is added to resolved as a dict-valued wc_file / ic_file (see parametric_cloud_profiles()) unless resolved already has that key. A dict-valued wc_file / ic_file is rendered as the placeholder wc_file 1D <generated: 2 levels, 1-2 km>. Only run_simulation() writes the cloud file, and it passes the path here instead of the dict.

The resolved parameters are then applied in mapping order. Each one removes every existing line with the same keyword and appends its own line(s) at the end:

  • False: remove only (switch a config-supplied option off);

  • a list: one line per element (repeatable options such as wc_modify);

  • a key of REGISTRY: formatted by its format_line() (mol_modify O3 320 DU);

  • True, None or "" on any other key: the bare keyword (flag options such as aerosol_default);

  • anything else: "<key> <value>".

Special cases: sza, sur_temperature, albedo and zout in resolved suppress the corresponding config line; output_user is merged through effective_output_columns(); brdf_rpv_type drops any albedo line (config or resolved) and adds brdf_rpv_library IGBP unless albedo_library, brdf_rpv_library or brdf_rpv_file is given. The file always ends with quiet.

Examples

InputFileBuilder shows a complete annotated input file. Per-point values carry the dataset-var tag:

>>> lines = builder.build(  
...     datetime(2024, 6, 21, 12), 78.9, 11.9,
...     {"albedo": (0.82, "dataset-var")},
... )
>>> [ln for ln in lines if ln.keyword == "albedo"]  
[InputLine(keyword='albedo', text='albedo 0.82', provenance='dataset-var')]
static render(lines)[source]#

Render lines as plain uvspec input file content.

Parameters:

lines (list of InputLine) – Lines from build().

Returns:

str – One text per line, newline-terminated: the content of the .inp file passed to uvspec.

Examples

>>> from pyradtran.input_builder import InputFileBuilder, InputLine
>>> lines = [
...     InputLine("albedo", "albedo 0.85", "params-literal"),
...     InputLine("sza", "sza 55.45", "config"),
...     InputLine("quiet", "quiet", "config"),
... ]
>>> print(InputFileBuilder.render(lines), end="")
albedo 0.85
sza 55.45
quiet
static render_annotated(lines)[source]#

Render lines with aligned # <provenance> annotations.

explain() returns this text. It is for reading, not for uvspec.

Parameters:

lines (list of InputLine) – Lines from build().

Returns:

str – Each line padded to a common width and followed by # <provenance>, newline-terminated. Empty for an empty list.

Examples

>>> from pyradtran.input_builder import InputFileBuilder, InputLine
>>> lines = [
...     InputLine("albedo", "albedo 0.85", "params-literal"),
...     InputLine("sza", "sza 55.45", "config"),
...     InputLine("quiet", "quiet", "config"),
... ]
>>> print(InputFileBuilder.render_annotated(lines), end="")
albedo 0.85  # params-literal
sza 55.45    # config
quiet        # config
