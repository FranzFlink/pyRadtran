pyradtran.era5.select_profile#

select_profile(ds, latitude=None, longitude=None, time=None)[source]#

Select a single vertical profile from a (normalised) ERA5 dataset.

Works on datasets with spatial/time dimensions and on ones already reduced to a single column. Selection is nearest-neighbour without a distance tolerance: a point outside the domain or time range returns the closest edge column. A warning is logged when that column is more than 1° from the requested position.

Parameters:

  • ds (xarray.Dataset) – ERA5 dataset on canonical names (see normalize_era5()); the function looks for the dimensions latitude, longitude, valid_time and pressure_level and does not normalise names itself.

  • latitude (float, optional) – Target position in degrees north and east. The longitude may be given in either convention (0…360 or −180…180); it is wrapped into the one the dataset uses. Required when ds has a latitude or longitude dimension, ignored otherwise.

  • longitude (float, optional) – Target position in degrees north and east. The longitude may be given in either convention (0…360 or −180…180); it is wrapped into the one the dataset uses. Required when ds has a latitude or longitude dimension, ignored otherwise.

  • time (str, datetime.datetime or numpy.datetime64, optional) – Target time, parsed with pandas.to_datetime(). Required when ds has a valid_time dimension, ignored otherwise.

Returns:

xarray.Dataset – Profile with pressure_level as the only remaining dimension, loaded into memory. The selected latitude / longitude / valid_time remain as scalar coordinates.

Raises:

ValueError – If ds has spatial dimensions but latitude or longitude is None, or has a valid_time dimension but time is None.

See also

normalize_era5

Bring any ERA5 flavour onto the names expected here.

write_atmosphere_file, cloud_profiles

Notes

Any other dimension still present after the selection (an ensemble number, expver, …) is reduced by taking its first element.

A dataset whose largest longitude exceeds 180 is taken to use 0…360, any other −180…180. The nearest-neighbour search is not cyclic: on a global 0…360 grid a request just west of 0° picks the last column, not the first (at most one grid cell off).

Examples

>>> import numpy as np
>>> import xarray as xr
>>> from pyradtran.era5 import select_profile
>>> era5 = xr.Dataset(
...     {
...         "t": (
...             ("valid_time", "pressure_level", "latitude", "longitude"),
...             250.0 + np.arange(2 * 3 * 3 * 4).reshape(2, 3, 3, 4),
...         )
...     },
...     coords={
...         "valid_time": np.array(
...             ["2024-07-15T00", "2024-07-15T06"], dtype="datetime64[ns]"
...         ),
...         "pressure_level": [500.0, 850.0, 1000.0],
...         "latitude": [79.0, 78.5, 78.0],
...         "longitude": [14.0, 15.0, 16.0, 17.0],
...     },
... )
>>> profile = select_profile(
...     era5, latitude=78.4, longitude=15.2, time="2024-07-15T05:00"
... )
>>> profile.t.dims
('pressure_level',)
>>> float(profile.latitude), float(profile.longitude)
(78.5, 15.0)
>>> str(profile.valid_time.values)[:13]
'2024-07-15T06'
>>> profile.t.values
array([291., 303., 315.])

The longitude convention of the request does not matter (15.2° E is 15.2 − 360 = −344.8):

>>> float(select_profile(era5, 78.4, -344.8, "2024-07-15T05:00").longitude)
15.0

A gridded dataset needs a position:

>>> select_profile(era5, time="2024-07-15T05:00")

    ...
