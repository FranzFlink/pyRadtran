pyradtran.params.ParamResolver#

class ParamResolver(config, params=None, schema='auto')[source]#

Bases: object

Resolve a user params mapping into validated per-point values.

The engine behind the params argument of run() and explain(). It

  • applies and consumes dotted config overrides ("simulation_defaults.albedo_value") on config; they never reach the uvspec input file directly;

  • splits the remaining entries into literals (validated in the constructor) and Var references (validated per point, in resolve_point());

  • tags every value with its provenance (PROV_* constants).

Parameters:

  • config (SimulationConfig) – Configuration of the run. Mutated in place by dotted keys.

  • params (dict, optional) – The user mapping; see the module docstring of pyradtran.params for the accepted keys and values.

  • schema ({“auto”, None} or dict, default "auto") – libRadtran option schema used to validate keys outside the curated REGISTRY. "auto" discovers it from config (get_schema()); None disables schema validation (registry only; unknown keys pass through as unvalidated); a dict is used as given (tests).

config#

The (possibly modified) configuration.

Type:

SimulationConfig

schema#

The schema in use.

Type:

dict or None

var_refs#

{key: Var} for all per-point references.

Type:

dict

Raises:

ValidationError – If any literal value fails validation, a key is not a known uvspec option, or a dotted key names no <section>.<field> of the configuration. All offending entries are reported in one exception.

See also

Var, Raw

pyradtran.input_builder.InputFileBuilder.build

Consumes the resolved mapping.

Notes

How one literal entry is validated:

  1. False is kept as is (it tells the builder to omit the option); Raw values are unwrapped and tagged unvalidated.

  2. A key of REGISTRY is checked by its ParamSpec.validate() (lists and tuples are space-joined first). If the value is a string and a schema is available, its tokens are additionally checked by validate_against_schema().

  3. Any other key is looked up in the schema by its first word. An unknown option raises, with close-match suggestions; a known one is checked by validate_against_schema(). A list on a repeatable (non_unique) option is validated element-wise and kept as a list of lines; other lists and tuples are space-joined.

  4. Without a schema, non-registry keys are accepted as they are and tagged unvalidated.

A dotted key that names no existing <section>.<field> of the configuration raises, with close-match suggestions. Afterwards config.simulation_defaults is re-validated (SimulationDefaults.validate), so an invalid value set through a dotted key or by attribute assignment is reported here too. rte_solver is checked against the schema; without one, against the solver list of libRadtran 2.0.6.

Examples

The examples use schema=None and a stand-in configuration so that they run without libRadtran; normally config comes from load_config() and the schema is discovered automatically.

>>> from types import SimpleNamespace
>>> from pyradtran import ParamResolver, Raw, Var
>>> from pyradtran.config import SimulationDefaults
>>> config = SimpleNamespace(simulation_defaults=SimulationDefaults())
>>> resolver = ParamResolver(
...     config,
...     {
...         "albedo": 0.85,
...         "zout": [0, 5],
...         "mol_modify O3": False,
...         "pseudospherical": Raw(True),
...         "sur_temperature": Var("tsurf"),
...         "simulation_defaults.rte_solver": "disort",
...     },
...     schema=None,
... )

Literals are available immediately, with their provenance:

>>> resolver.static_params()
{'albedo': (0.85, 'params-literal'), 'zout': ('0 5', 'params-literal'), 'mol_modify O3': (False, 'params-literal'), 'pseudospherical': (True, 'unvalidated')}

The reference waits for a dataset, and the dotted key went into the configuration:

>>> resolver.var_refs
{'sur_temperature': Var(name='tsurf')}
>>> config.simulation_defaults.rte_solver
'disort'

All invalid literals are reported together:

>>> ParamResolver(config, {"albedo": 1.5, "sza": 999.0}, schema=None)
Traceback (most recent call last):
    ...
pyradtran.exceptions.ValidationError: Invalid parameter value(s): 'albedo' must be in [0.0, 1.0], got 1.5; 'sza' must be in [0.0, 180.0] deg, got 999.0

With a schema, non-registry options are validated too. A list on a repeatable option becomes one input line per element:

>>> schema = {
...     "wc_modify": {
...         "name": "wc_modify",
...         "non_unique": True,
...         "tokens": [
...             {"kind": "choice", "choices": ["gg", "ssa", "tau", "tau550"]},
...             {"kind": "choice", "choices": ["set", "scale"]},
...             {"kind": "value", "datatype": "float"},
...         ],
...     },
...     "aerosol_default": {"name": "aerosol_default", "tokens": []},
... }
>>> ParamResolver(
...     config,
...     {"wc_modify": ["tau550 set 12", "gg set 0.85"], "aerosol_default": True},
...     schema=schema,
... ).static_params()
{'wc_modify': (['tau550 set 12', 'gg set 0.85'], 'params-literal'), 'aerosol_default': (True, 'params-literal')}
>>> ParamResolver(config, {"wc_modfy": "tau550 set 12"}, schema=schema)
Traceback (most recent call last):
    ...
pyradtran.exceptions.ValidationError: Invalid parameter value(s): 'wc_modfy' is not a known uvspec option of the local libRadtran install; did you mean wc_modify / mol_modify? (wrap the value in Raw(...) to bypass validation)

A misspelt configuration path is also an error:

>>> ParamResolver(config, {"simulation_defaults.rte_solvr": "disort"}, schema=None)
Traceback (most recent call last):
    ...
pyradtran.exceptions.ValidationError: Invalid parameter value(s): 'simulation_defaults.rte_solvr' is not a configuration field; did you mean simulation_defaults.rte_solver?

static_params()[source]#

Return key -> (value, provenance) for point-independent values.

Returns:

dict – A copy of the validated literal entries: plain values tagged params-literal, Raw values (and, without a schema, non-registry keys) tagged unvalidated, and False for options to omit. Var references are not included; see resolve_point().

Examples

>>> from types import SimpleNamespace
>>> from pyradtran import ParamResolver, Var
>>> resolver = ParamResolver(
...     SimpleNamespace(),
...     {"albedo": 0.85, "wavelength": (400, 700), "sza": Var("sza")},
...     schema=None,
... )
>>> resolver.static_params()
{'albedo': (0.85, 'params-literal'), 'wavelength': ('400 700', 'params-literal')}
validate_var_targets(ds)[source]#

Check Var targets and ambiguous strings against ds.

Called once per run, before any point is resolved, so that a misspelt variable name fails before any simulation starts.

Parameters:

ds (xarray.Dataset) – The input dataset of the run.

Raises:

ValidationError – If a Var names a variable missing from ds, or if a bare string literal matches a dataset variable name (ambiguous; the user almost certainly meant Var). All problems are reported in one exception.

Examples

>>> import xarray as xr
>>> from types import SimpleNamespace
>>> from pyradtran import ParamResolver, Var
>>> ds = xr.Dataset({"tsurf": ("time", [271.3, 268.9])})
>>> config = SimpleNamespace()
>>> ParamResolver(
...     config, {"sur_temperature": Var("tsurf")}, schema=None
... ).validate_var_targets(ds)

A forgotten Var; the string would otherwise be written to the input file literally:

>>> ParamResolver(
...     config, {"sur_temperature": "tsurf"}, schema=None
... ).validate_var_targets(ds)
Traceback (most recent call last):
    ...
pyradtran.exceptions.ValidationError: 'sur_temperature' has string value 'tsurf' which matches a dataset variable name; use Var('tsurf') for a per-point reference or change the literal
resolve_point(point_ds)[source]#

Resolve all parameters for one stacked point.

Parameters:

point_ds (xarray.Dataset) – A single point (0-d variables), as produced by stacked_ds.isel({sample_dim: i}).

Returns:

  • resolved (dict) – key -> (value, provenance) merged from literals and per-point references. Values from a Var are tagged dataset-var.

  • skipped (list of str) – Keys omitted for this point because the dataset value was NaN. They are absent from resolved, so the configuration’s own line for that option (if any) stays in effect.

Raises:

ValidationError – If a referenced variable is missing from point_ds, or a per-point value fails the same validation a literal would get. All problems of the point are reported together.

Examples

>>> import numpy as np
>>> import xarray as xr
>>> from types import SimpleNamespace
>>> from pyradtran import ParamResolver, Var
>>> ds = xr.Dataset({"tsurf": ("time", [271.3, np.nan])})
>>> resolver = ParamResolver(
...     SimpleNamespace(),
...     {"albedo": 0.85, "sur_temperature": Var("tsurf")},
...     schema=None,
... )
>>> resolved, skipped = resolver.resolve_point(ds.isel(time=0))
>>> resolved
{'albedo': (0.85, 'params-literal'), 'sur_temperature': (271.3, 'dataset-var')}
>>> skipped
[]

At the second point the temperature is NaN and is left out:

>>> resolver.resolve_point(ds.isel(time=1))
({'albedo': (0.85, 'params-literal')}, ['sur_temperature'])
