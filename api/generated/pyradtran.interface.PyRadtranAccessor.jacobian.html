pyradtran.interface.PyRadtranAccessor.jacobian#

PyRadtranAccessor.jacobian(param, delta, params=None, config_path=None, config=None, **run_kwargs)[source]#

Finite-difference sensitivity kernel for one scalar parameter.

Runs the batch twice, with the base value of param and with param + delta, and returns the difference quotient of every output variable on the dimensions of run().

Parameters:

  • param (str) – Parameter to perturb, as written in params ("albedo", "sza", "mol_modify O3" …). Its base value must be a single number: a literal in params, or one of the configuration defaults albedo, sur_temperature, sza, mol_modify O3 and mol_modify H2O. A Var is not allowed.

  • delta (float) – Perturbation \(\delta\) in the units of the parameter. Negative values give a backward difference.

  • params (dict, optional) – Base parameter mapping, as in run(). Other entries may be Var references.

  • config_path (str or pathlib.Path, optional) – Simulation YAML, as in run().

  • config (SimulationConfig, optional) – Pre-built configuration; takes precedence over config_path.

  • **run_kwargs – Forwarded to both run() calls (e.g. show_progress=False, era5_atmosphere=...). save_to_file defaults to False here; return_dataset=False is not allowed.

Returns:

xarray.Dataset – Variables and dimensions of a run() result, holding the derivative with respect to param (output units per unit of param). status is the larger status of the two runs per point; a point that failed in either run is NaN. Attributes: jacobian_param, jacobian_delta, jacobian_base_value and the usual provenance of the base run.

Raises:

ValidationError – If param is a Var reference, has no base value in params or the configuration (e.g. "sza" when it is computed from time and position), or has a non-numeric one ("rte_solver"); also for return_dataset=False.

See also

run

The simulation that is differentiated.

Notes

For an output \(F\) and parameter \(x\) with base value \(x_0\), the kernel is the forward difference

\[K = \frac{F(x_0 + \delta) - F(x_0)}{\delta} = \left.\frac{\partial F}{\partial x}\right|_{x_0} + \frac{\delta}{2}\, \left.\frac{\partial^2 F}{\partial x^2}\right|_{x_0} + \mathcal{O}(\delta^2)\]

so the truncation error grows linearly with \(\delta\). A very small \(\delta\) does not help: uvspec prints about seven significant digits, so the difference of two outputs has a round-off error of order \(\varepsilon |F|\) with \(\varepsilon \approx 10^{-7}\), which the division amplifies to

\[\Delta K_\mathrm{round} \approx \frac{\varepsilon\,|F|}{\delta}\]

Choose \(\delta\) between the two regimes: large enough that the outputs change in their first four or five digits, small enough that the response is linear. About 1 % of the parameter’s natural range usually works (0.01 for an albedo, 1 K for a temperature, a few DU for ozone). To check, repeat with \(\delta/2\) or \(-\delta\): if the kernel changes noticeably, the truncation term matters. Monte Carlo solvers (mystic) add statistical noise to \(\Delta K_\mathrm{round}\) and need a larger \(\delta\).

The cost is two full batches. All other inputs (Var parameters, clouds, ERA5 profiles) are identical in both runs.

Examples

Surface irradiances against surface albedo at local noon (base value 0.15 from the configuration):

>>> import pandas as pd
>>> import xarray as xr
>>> import pyradtran
>>> noon = xr.Dataset(
...     coords={
...         "time": [pd.Timestamp("2025-06-21T12:00")],
...         "latitude": ("time", [61.0]),
...         "longitude": ("time", [22.0]),
...     }
... )
>>> kernel = noon.pyradtran.jacobian(  
...     "albedo",
...     0.01,
...     config_path="config/quickstart.yaml",
...     params={"rte_solver": "disort", "wavelength": [400, 700]},
...     show_progress=False,
... )
>>> dict(kernel.sizes)  
{'time': 1, 'wavelength': 301, 'altitude': 1}
>>> {k: v for k, v in kernel.attrs.items() if k.startswith("jacobian")}  
{'jacobian_param': 'albedo', 'jacobian_delta': 0.01, 'jacobian_base_value': 0.15}

eup responds strongly, edn through multiple reflection between surface and atmosphere (more in the blue), edir not at all:

>>> sel = kernel.sel(wavelength=[450, 550, 650]).squeeze()  
>>> sel.eup.round(1).values  
array([1439.8, 1307.6, 1071.7])
>>> sel.edn.round(1).values  
array([234.9, 105.7,  46.1])
>>> sel.edir.round(1).values  
array([0., 0., 0.])

Step size and d eup / d albedo at 550 nm: round-off noise, a plateau, then curvature:

>>> for delta in (1e-6, 1e-4, 1e-2, 1e-1, 0.5):  
...     k = noon.pyradtran.jacobian(
...         "albedo", delta, config_path="config/quickstart.yaml",
...         params={"rte_solver": "disort", "wavelength": [550, 550]},
...         show_progress=False,
...     )
...     print(f"{delta:8.0e}  {float(k.eup.squeeze()):8.1f}")
   1e-06    1300.0
   1e-04    1306.0
   1e-02    1307.6
   1e-01    1317.4
   5e-01    1362.3

Without a configuration default, give the base value in params:

>>> kernel = noon.pyradtran.jacobian(  
...     "sza",
...     1.0,
...     config_path="config/quickstart.yaml",
...     params={"sza": 40.0, "wavelength": [550, 550]},
...     show_progress=False,
... )
>>> round(float(kernel.edir.squeeze()), 2)  # per degree  
-20.65
