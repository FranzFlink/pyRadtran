class SimulationConfig(paths, simulation_defaults, execution=<factory>, output=<factory>)[source]#

Bases: object

Top-level configuration container.

Four sections that mirror the top-level keys of the YAML file. Build an instance with load_config() (three merged layers) or from_yaml() (one self-contained file).

Parameters:

  • paths (PathsConfig) – File-system paths: libRadtran installation, atmosphere profile, solar spectrum, output and working directories.

  • simulation_defaults (SimulationDefaults) – Physics and spectral settings written to the uvspec input.

  • execution (ExecutionConfig, optional) – Parallelism, timeout and debugging.

  • output (OutputConfig, optional) – NetCDF file naming and encoding.

See also

load_config

Recommended entry point (merges three layers).

pyradtran.interface.PyRadtranAccessor.run

Accepts an instance via config=.

Notes

A plain mutable dataclass: change a setting by assigning to the attribute. ds.pyradtran.run(config=cfg) works on a copy(), so its per-run adjustments (dataset-derived output altitudes, dotted keys in params) never leak back into cfg.

Examples

Load, modify, run and save:

>>> from pyradtran import load_config
>>> cfg = load_config()  
>>> cfg.simulation_defaults.rte_solver = "disort"  
>>> cfg.simulation_defaults.integrate_wavelength = True  
>>> cfg.execution.max_workers = 1  
>>> result = ds.pyradtran.run(config=cfg, save_to_file=False)  
>>> cfg.to_yaml("config/broadband_disort.yaml")  
PosixPath('config/broadband_disort.yaml')

classmethod from_yaml(yaml_path)[source]#

Load configuration from a single, self-contained YAML file.

Unlike load_config() nothing is merged: neither the package defaults nor ~/.pyradtran/config.yaml are read. Missing keys take the dataclass defaults, so the file needs at least paths (with libradtran_bin and libradtran_data) and simulation_defaults (which may be empty, {}).

Parameters:

yaml_path (str or pathlib.Path) – Path to the YAML file.

Returns:

SimulationConfig

Raises:

  • ConfigurationError – If yaml_path does not exist or the paths in it fail the PathsConfig checks (also a FileNotFoundError), or a value fails the SimulationDefaults validation (also a ValueError).

  • TypeError – If a required section or key is missing.

See also

load_config

Layered loading; the usual entry point.

to_yaml

Writes a file this method can read back.

Notes

Unknown keys are ignored with a logged warning. Scalars are coerced to the annotated field type where possible ("0.2" becomes 0.2 for a float field); path strings become pathlib.Path with ~ expanded.

Examples

Load a configuration exactly as saved, independent of the master config of the current machine:

>>> from pyradtran import SimulationConfig
>>> cfg = SimulationConfig.from_yaml("config/my_simulation.yaml")  
>>> cfg.simulation_defaults.rte_solver  
'disort'
copy()[source]#

Return an independent deep copy of this configuration.

Only clouds.era5_dataset (potentially a large xarray Dataset) is shared by reference. The accessor runs on a copy, so per-run adjustments (dataset-derived zout levels, dotted config overrides in params) never mutate the caller’s object.

Returns:

SimulationConfig

Examples

Derive a variant of a base configuration for a sensitivity study:

>>> base = load_config()  
>>> dark = base.copy()  
>>> dark.simulation_defaults.albedo_value = 0.06  
>>> base.simulation_defaults.albedo_value  
0.85
to_dict()[source]#

Serialise the full configuration to a plain nested dict.

Path objects become strings and the non-serialisable clouds.era5_dataset entry is dropped, so the result can be written to YAML.

Returns:

dict – Nested dictionary mirroring the YAML structure, with the top-level keys paths, simulation_defaults, execution and output. Every field is present, including those still at their default.

See also

to_yaml

Write the result directly to a file.

get_used_parameters

A similar, hand-picked summary.

Examples

>>> cfg = load_config()  
>>> d = cfg.to_dict()  
>>> sorted(d)  
['execution', 'output', 'paths', 'simulation_defaults']
>>> d["paths"]["atmosphere_profile"]  
'/opt/libRadtran-2.0.6/data/atmmod/afglus.dat'
>>> d["execution"]  
{'max_workers': 4, 'cleanup_temp_files': False, 'debug_mode': False, 'timeout_seconds': 300}
to_yaml(path)[source]#

Write the configuration to a YAML file.

The file contains every setting (the output of to_dict(), keys sorted alphabetically), so it documents a run completely and can be read back with load_config() or from_yaml().

Parameters:

path (str or pathlib.Path) – Destination file. Parent directories are created; an existing file is overwritten.

Returns:

pathlib.Path – path as a Path (not made absolute).

See also

load_config

Read the file back.

save_master_config

Store only the machine-specific paths.

Notes

The complete file also pins the resolved, machine-specific paths section, which overrides the master config wherever the file is loaded. Delete the paths block to make the file portable between machines.

Examples

Change the defaults and save:

>>> from pyradtran import load_config
>>> cfg = load_config()  
>>> cfg.simulation_defaults.albedo_value = 0.2  
>>> cfg.simulation_defaults.wavelength_nm = [500, 600]  
>>> cfg.simulation_defaults.rte_solver = "disort"  
>>> cfg.to_yaml("config/my_simulation.yaml")  
PosixPath('config/my_simulation.yaml')

The written file (shortened):

execution:
  cleanup_temp_files: false
  debug_mode: false
  max_workers: 4
  timeout_seconds: 300
output:
  filename_prefix: pyradtran_sim
  ...
paths:
  atmosphere_profile: /opt/libRadtran-2.0.6/data/atmmod/afglus.dat
  libradtran_bin: /opt/libRadtran-2.0.6/bin/uvspec
  libradtran_data: /opt/libRadtran-2.0.6/data
  ...
simulation_defaults:
  albedo_value: 0.2
  ...
  rte_solver: disort
  source: solar
  ...
  wavelength_nm:
  - 500
  - 600
get_used_parameters()[source]#

Return a nested summary dict of the active parameters.

For logging. The four sections of to_dict() with all paths as strings, but without simulation_defaults.parameter_overrides and the clouds.era5_* entries.

Returns:

dict – {"paths": {...}, "simulation_defaults": {..., "clouds": {...}}, "execution": {...}, "output": {...}}. Lists and dicts inside are the config’s own objects, not copies.

See also

to_dict

Complete, YAML-serialisable representation.

Examples

>>> cfg = load_config()  
>>> used = cfg.get_used_parameters()  
>>> sorted(used)  
['execution', 'output', 'paths', 'simulation_defaults']
>>> used["simulation_defaults"]["rte_solver"]  
'twostr'
