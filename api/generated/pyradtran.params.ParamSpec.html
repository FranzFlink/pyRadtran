pyradtran.params.ParamSpec#

class ParamSpec(keyword, dtype=<class 'float'>, units=None, valid_range=None, choices=None, applicability='both', formatter=None, doc='')[source]#

Bases: object

Declarative description of one curated uvspec parameter.

The entries of REGISTRY are instances of this class. A spec knows how to check a value (validate()) and how to write the input line (format_line()).

Parameters:

  • keyword (str) – The uvspec keyword (possibly multi-word, e.g. "mol_modify O3").

  • dtype (type, default float) – Expected scalar type. Values are not converted. When this is float or int, validate() rejects booleans and applies the range check.

  • units (str, optional) – Physical units, for documentation and error messages.

  • valid_range (tuple of float, optional) – Inclusive (lo, hi) range for numeric values.

  • choices (tuple, optional) – Allowed values for enumerated parameters (exact, case-sensitive match).

  • applicability ({"both", "solar", "thermal"}) – Which source modes the parameter applies to. Informational only; not enforced.

  • formatter (callable, optional) – value -> full input line. Defaults to "{keyword} {value}".

  • doc (str, default "") – One-line description.

See also

REGISTRY

The curated specs shipped with pyradtran.

validate_against_schema

Validation of all other uvspec options.

Examples

A spec from the registry:

>>> from pyradtran import REGISTRY
>>> spec = REGISTRY["mol_modify O3"]
>>> spec.units, spec.valid_range
('DU', (0.0, 1000.0))
>>> spec.format_line(320)
'mol_modify O3 320 DU'

Defining one (specs are plain frozen dataclasses):

>>> from pyradtran import ParamSpec
>>> pressure = ParamSpec("pressure", float, "hPa", (0, 1100), doc="Surface pressure")
>>> pressure.format_line(950.0)
'pressure 950.0'
>>> pressure.validate(2000)
Traceback (most recent call last):
    ...
pyradtran.exceptions.ValidationError: 'pressure' must be in [0, 1100] hPa, got 2000.0

validate(value)[source]#

Raise ValidationError if value is out of spec.

Parameters:

value (Any) – The candidate value.

Returns:

None – The value is not converted or returned.

Raises:

ValidationError – If the spec has choices and value is not one of them; or the spec is numeric and value is a bool; or the spec is numeric with a valid_range and value is not a number or lies outside the (inclusive) range.

Notes

The checks, in order:

  1. A spec with choices accepts exactly those values.

  2. Otherwise a str is accepted as is, which allows raw uvspec syntax such as "0 toa" for zout. (ParamResolver also checks such strings against the libRadtran option schema when one is available.)

  3. Otherwise a float / int spec rejects True / False (a boolean is a flag, not a number).

  4. Otherwise, for float / int specs with a valid_range, the value must convert with float and satisfy lo <= value <= hi.

Specs without choices and without valid_range (e.g. wavelength, zout) accept anything but a boolean.

Examples

>>> from pyradtran import REGISTRY
>>> REGISTRY["albedo"].validate(0.3)  # fine: returns None
>>> REGISTRY["albedo"].validate(1.5)
Traceback (most recent call last):
    ...
pyradtran.exceptions.ValidationError: 'albedo' must be in [0.0, 1.0], got 1.5

Units are part of the message where the spec has them:

>>> REGISTRY["sza"].validate(200)
Traceback (most recent call last):
    ...
pyradtran.exceptions.ValidationError: 'sza' must be in [0.0, 180.0] deg, got 200.0

Enumerated parameters:

>>> REGISTRY["source"].validate("lunar")
Traceback (most recent call last):
    ...
pyradtran.exceptions.ValidationError: 'source' must be one of ('solar', 'thermal'), got 'lunar'

A boolean is not a number:

>>> REGISTRY["albedo"].validate(True)
Traceback (most recent call last):
    ...
pyradtran.exceptions.ValidationError: 'albedo' expects a number, got True
format_line(value)[source]#

Render the full uvspec input line for value.

Parameters:

value (Any) – The (already validated) value.

Returns:

str – The spec’s formatter(value) if it has one, otherwise "<keyword> <value>".

Examples

>>> from pyradtran import REGISTRY
>>> REGISTRY["albedo"].format_line(0.3)
'albedo 0.3'

Custom formatters append units, cast to integer, or tidy lists. zout levels are sorted and de-duplicated, because uvspec rejects anything else:

>>> REGISTRY["mol_modify H2O"].format_line(14.5)
'mol_modify H2O 14.5 MM'
>>> REGISTRY["mol_modify O3"].format_line("320 DU")  # unit given: kept
'mol_modify O3 320 DU'
>>> REGISTRY["brdf_rpv_type"].format_line(7.0)
'brdf_rpv_type 7'
>>> REGISTRY["zout"].format_line([10, 0, 2, 2])
'zout 0 2 10'
>>> REGISTRY["zout"].format_line("0 toa")
'zout 0 toa'
