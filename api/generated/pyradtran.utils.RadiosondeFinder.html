pyradtran.utils.RadiosondeFinder#

class RadiosondeFinder(base_path)[source]#

Bases: object

Locate the radiosonde file closest in time to a target datetime.

The constructor scans base_path recursively for files named YYYYMMDD_SSSSSSOD.dat: the launch date followed by the five-digit seconds of day (UTC), e.g. 20220328_43200SOD.dat for a sounding at 12:00 UTC on 28 March 2022. find_closest() then does a binary search on the time-sorted file list.

Parameters:

base_path (pathlib.Path or None) – Root directory to scan. If None (or not an existing directory), nothing is indexed and all look-ups return None.

base_path#

The directory given at construction.

Type:

pathlib.Path or None

See also

pyradtran.io.RadiosondeAtmosphereGenerator

Fetch soundings from IGRA.

pyradtran.config.PathsConfig

radiosonde_base is the directory handed to this class during a simulation.

Notes

A file name with date \(d\) and seconds of day \(s\) is assigned the time

\[t = d\ \text{00:00 UTC} + s\ \mathrm{seconds}, \qquad 0 \le s \le 99999 .\]

.dat files that do not match the pattern are ignored, as are files whose date part is not a valid calendar date (with a logged warning). Only the file name is used; the contents are never read here. The index is built once: files added later are not seen until a new finder is created.

The files are three-column tables (pressure in hPa, temperature in K, relative humidity in %), ordered from the top of the sounding downwards, as uvspec’s radiosonde ... H2O RH option expects.

Examples

An archive with one directory per flight:

>>> import tempfile
>>> from datetime import datetime
>>> from pathlib import Path
>>> from pyradtran import RadiosondeFinder
>>> root = Path(tempfile.mkdtemp())
>>> for name in [
...     "Flight_20220328/20220328_37218SOD.dat",
...     "Flight_20220328/20220328_45046SOD.dat",
...     "Flight_20220329/20220329_40000SOD.dat",
...     "Flight_20220329/notes.dat",
... ]:
...     (root / name).parent.mkdir(exist_ok=True)
...     (root / name).touch()
>>> finder = RadiosondeFinder(root)

37218 s is 10:20 UTC and 45046 s is 12:31 UTC, so 11:00 UTC matches the first sounding and 12:00 UTC the second:

>>> finder.find_closest(datetime(2022, 3, 28, 11, 0)).name
'20220328_37218SOD.dat'
>>> finder.find_closest(datetime(2022, 3, 28, 12, 0)).name
'20220328_45046SOD.dat'

Times outside the covered period get the first or last sounding:

>>> finder.find_closest(datetime(2023, 1, 1)).name
'20220329_40000SOD.dat'

Without a directory nothing is found:

>>> RadiosondeFinder(None).find_closest(datetime(2022, 3, 28)) is None
True

find_closest(target_dt, max_hours=None)[source]#

Return the radiosonde file closest in time to target_dt.

Parameters:

  • target_dt (datetime.datetime) – Target time. Naive values are taken as UTC; aware values are converted to UTC.

  • max_hours (float, optional) – Largest accepted time difference in hours. Default: no limit.

Returns:

pathlib.Path or None – Path of the closest file (below base_path, absolute if base_path is), or None when no files are indexed or the closest one is more than max_hours away.

Notes

The result minimises \(|t_i - t|\) over all indexed sounding times \(t_i\). Without max_hours, a target before the first (after the last) sounding returns the first (last) file, however far away. A warning is logged when the returned sounding is more than 12 h from the target. Exactly halfway between two soundings, the earlier one is returned.

Examples

>>> import tempfile
>>> from datetime import datetime, timedelta, timezone
>>> from pathlib import Path
>>> from pyradtran import RadiosondeFinder
>>> root = Path(tempfile.mkdtemp())
>>> for name in ["20220328_36000SOD.dat", "20220328_43200SOD.dat"]:
...     (root / name).touch()
>>> finder = RadiosondeFinder(root)
>>> finder.find_closest(datetime(2022, 3, 28, 10, 30)).name
'20220328_36000SOD.dat'

Halfway (11:00 UTC between 10:00 and 12:00), the earlier sounding wins:

>>> finder.find_closest(datetime(2022, 3, 28, 11, 0)).name
'20220328_36000SOD.dat'

Aware datetimes are converted (13:30 at UTC+2 is 11:30 UTC):

>>> cest = timezone(timedelta(hours=2))
>>> finder.find_closest(datetime(2022, 3, 28, 13, 30, tzinfo=cest)).name
'20220328_43200SOD.dat'

Without a limit, a sounding months away is still returned:

>>> finder.find_closest(datetime(2022, 9, 1)).name
'20220328_43200SOD.dat'
>>> finder.find_closest(datetime(2022, 9, 1), max_hours=6) is None
True
find_radiosonde_file(dt, latitude, longitude)[source]#

Find the radiosonde file closest in time to dt.

The simulation engine calls this for every point when simulation_defaults.h2o_source is "radiosonde". It delegates to find_closest(); the position is ignored.

Parameters:

  • dt (datetime.datetime) – Target time (UTC if timezone-naive).

  • latitude (float) – Unused; reserved for spatial matching.

  • longitude (float) – Unused; reserved for spatial matching.

Returns:

pathlib.Path or None – Closest file in time, or None when no files are indexed.

See also

find_closest

The underlying time search.

Examples

>>> finder = RadiosondeFinder(Path("/data/halo_ac3/radiosonde"))  
>>> path = finder.find_radiosonde_file(  
...     datetime(2022, 3, 28, 11, 0), latitude=78.9, longitude=11.9
... )
